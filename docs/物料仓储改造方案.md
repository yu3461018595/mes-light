# 物料仓储模块升级方案（对齐蜂鸟工单库存结构）

> 状态：**阶段 1 已开发完成并通过本地验证（19/19 冒烟 + UI 端到端），未推送、未部署，等待确认**
> 目标：把现在的「两张孤立单据表」升级为「物料档案 + 库存台账 + 收发明细（流水）+ 出入库单据 + 预警」的完整库存闭环。

---

## 一、现状（已上线）

菜单：PC 端「物料仓储」（仅 admin/leader 可见），两个页签：

| 页签 | 表 | 主要字段 | 单号规则 |
|---|---|---|---|
| 来料记录 | `incoming_materials` | 来料日期、供应商、物料编码、物料名称、规格、数量、单位、批次、关联工单、检验员、检验结论（待检/合格/不合格）、备注 | `LM` + 日期 + 序号 |
| 成品入库 | `finished_goods_in` | 入库日期、关联工单、产品编码、产品名称、规格、数量、单位、批号、库位、质检员、质检结果、备注 | `RK` + 日期 + 序号 |

**现有短板（与蜂鸟对比）**
1. 只有单据，**没有库存台账** —— 查不到"现在还剩多少"。
2. **没有收发明细（流水）** —— 无法追溯"哪天出的、谁操作、关联哪张工单"。
3. **缺领料 / 退料 / 成品出库** —— 车间用了多少料、发了多少货没有记录。
4. **没有安全库存与预警** —— 缺料靠人发现。
5. **没有物料档案** —— 每次录单手打名称规格，容易一物多码。
6. 无多仓库/库位体系（目前只有一个"库位"文本框）。

---

## 二、改造后的目标结构

### 1. 物料档案 `materials`（新增）
物料/成品的统一主数据，录单时下拉选择，杜绝一物多码。

| 字段 | 说明 |
|---|---|
| code | 物料编码（唯一） |
| name | 名称 |
| spec | 规格型号 |
| material | 材质（选填） |
| category | 分类：原料 / 半成品 / 成品 / 外协件 |
| unit | 计量单位 |
| warehouse / location | 默认仓库、默认库位 |
| safe_min / safe_max | 安全库存下限 / 上限（用于预警） |
| enabled | 启用/停用 |

> 注：现有 `products`（产品）表继续用于工单产品，不动；`materials` 是仓储侧主数据，两者可各自独立，也可后期映射。

### 2. 仓库 / 库位 `warehouses`（新增，可精简）
先做一层：仓库名称 + 编号；库位保留为文本字段（如 `A-01-02`），不做货架三级。

### 3. 库存台账 `inventory`（新增，核心）
按「物料 + 仓库 + 批次」一行，实时反映当前库存。

- 字段：物料、仓库、库位、批次、**当前数量**、单位、最近入库日、最近出库日、更新时间
- 数量**由流水实时汇总**（写入单据时同步增减，禁止手改；手改只能走"盘点调整"）

### 4. 收发明细（库存流水）`inventory_tx`（新增，核心）
任何一笔库存变动都自动落一条流水，可追溯到单。

| 字段 | 说明 |
|---|---|
| material_id | 物料 |
| warehouse / location | 仓库、库位 |
| batch | 批次 |
| tx_type | 类型：来料入库 / 领料出库 / 退料入库 / 成品入库 / 成品出库 / 盘点调整 / 报废 |
| qty | 变动数量（正=入，负=出） |
| before_qty / after_qty | 变动前库存 / 变动后库存 |
| ref_type / ref_code | 关联单据类型 + 单号 |
| order_id | 关联生产工单 |
| operator | 操作人 |
| tx_time | 时间 |
| remark | 备注 |

### 5. 单据（入库/出库）
| 单据 | 现状 | 改造 |
|---|---|---|
| 来料单 | 已有 | 保留字段，提交/修改/删除时**自动写流水 + 更新台账** |
| 领料单 | 无 | **新增**：按工单领料（工单 + 物料 + 数量 + 领料人），库存减少 |
| 退料单 | 无 | **新增**：余料/不良退库，库存增加 |
| 成品入库单 | 已有 | 同来料单，接入流水 |
| 成品出库单 | 无 | **新增**：发货给客户（客户 + 产品 + 数量 + 关联工单），库存减少 |
| 盘点调整 | 无 | **新增（可选）**：盘盈盘亏调整，写"盘点调整"流水 |

### 6. 安全库存预警
- 台账列表：低于 `safe_min` 标红（缺料预警），高于 `safe_max` 标黄（积压提示）
- 仪表盘：显示"缺料物料数"卡片角标（可开关）

---

## 三、页面变化（PC「物料仓储」菜单）

页签由 2 个扩为 7 个：

`库存台账` ｜ `来料入库` ｜ `领料出库` ｜ `退料入库` ｜ `成品入库` ｜ `成品出库` ｜ `收发明细` ｜ `物料档案`

- 每个列表页：日期区间 / 物料 / 工单 / 仓库 / 类型 筛选 + 新增、编辑、删除 + **导出 CSV**
- 台账页：汇总行（物料种数、总库存金额可选）、预警高亮
- 收发明细页：默认只读（流水由单据生成，不允许手改），可按物料查看"一本账"
- 权限：admin/leader 可写可删；worker 只读（不建议开放，除非需要手机领料）

## 四、移动端（可选，第二阶段）
- 复用现有扫码风格：扫物料码 → 出入库快速录入（数量 + 类型 + 工单）
- Service Worker 缓存版本需再升一级

## 五、数据与迁移

- **纯新增 4~5 张表**（materials、warehouses、inventory、inventory_tx、领/退/出单据表），现有 `incoming_materials`、`finished_goods_in` 保留并补 `material_id`、`warehouse` 字段（可空），**历史数据不丢、不改**。
- 旧库升级用 `ALTER TABLE ... ADD COLUMN` 兼容（与现有迁移写法一致）。
- 初始化库存：提供一次性"按历史单据重算台账"按钮（默认不自动跑，避免把老数据算错）。
- 静态模式 `public/js/store.js` 需同步新增这几张表（若启用静态预览版）。

## 六、风险与影响面

- **不动**报工、工单、班组派工、薪资统计等现有逻辑，只在仓储菜单内新增。
- 单据删除/编辑要**事务回滚**：先冲销原流水、再重算该物料库存，避免出现负数或账实不符（会加"库存不足不允许出库"校验）。
- 部署需要 `docker compose build` 重建（前端烘焙在镜像里）。

## 七、建议分阶段（可只做其中一段）

- **阶段 1（核心闭环）**：物料档案 + 库存台账 + 收发明细 + 来料/成品入库接入流水 + 安全库存预警
- **阶段 2（车间流转）**：领料出库 / 退料入库 / 成品出库（按工单绑定，支持用料追溯）
- **阶段 3（移动化）**：手机扫码出入库 + 盘点调整单
